# API 명세

**이 문서는 구현된 것만 적습니다.** 계획은 "아직 없는 것" 절에 따로 모아 두었습니다.

기준은 코드입니다. 이 문서와 코드가 어긋나면 코드가 맞습니다.

| 확인할 것 | 볼 곳 |
| --- | --- |
| 요청·응답 모양 | `backend/api/src/main/java/com/nanumi/api/dto/` |
| 실제 스키마 | `backend/api/src/main/resources/db/migration/` |
| 오류 코드 목록 | `backend/api/src/main/java/com/nanumi/api/exception/ErrorCode.java` |

> `docs/excel/*.xlsx` 의 설계는 구현 이전에 그린 것입니다. `username`, `name`, `room_number`, 별도 `Auth_Tokens` 표, bcrypt 같은 항목은 **현재 구현과 다릅니다.** 처음 보는 사람은 Excel 이 아니라 이 문서와 마이그레이션을 기준으로 삼으십시오.

## 공통

모든 경로 앞에 `/api` 가 붙습니다. 본문은 JSON 입니다.

### 인증

인증이 필요한 요청은 액세스 토큰을 헤더에 실어 보냅니다.

```
Authorization: Bearer <accessToken>
```

| 토큰 | 수명 | 어디에 두는지 |
| --- | --- | --- |
| 액세스 토큰 | 15분 | 메모리만 (`localStorage` 에 남기지 않음) |
| 리프레시 토큰 | 14일 | `localStorage` |

서버는 리프레시 토큰의 **SHA-256 해시만** `refresh_tokens` 표에 담습니다. 기기마다 한 행이므로 여러 기기에서 동시에 로그인할 수 있고, 한 계정에 최대 5대까지입니다(넘으면 오래된 것부터 지워집니다).

### 오류 응답

모양이 하나로 통일되어 있습니다.

```json
{ "status": 401, "message": "유효하지 않은 토큰입니다." }
```

검증 실패(400)는 `message` 에 첫 번째 위반 사유가 담깁니다. 예: `"비밀번호는 8자 이상이어야 합니다."`

| 상태 | 언제 |
| --- | --- |
| 400 | 입력 형식이 맞지 않음 |
| 401 | 자격 증명·토큰 문제 |
| 403 | 권한 없음, 또는 이미 탈퇴한 계정 |
| 404 | 대상이 없음 |
| 409 | 이메일·닉네임 중복 |
| 429 | 시도 횟수 초과 |
| 500 | 서버 오류 (원인은 응답에 담지 않고 로그에만 남김) |

## POST /api/auth/signup

회원가입. 인증 필요 없음.

```json
{
  "email": "nanumi@example.com",
  "password": "Ab3!efgh",
  "nickname": "나눔이",
  "aptName": "행복아파트",
  "dong": "101",
  "ho": "1502"
}
```

| 항목 | 필수 | 제약 |
| --- | --- | --- |
| `email` | ✅ | 100자 이하, 형식 검사 |
| `password` | ✅ | 8~20자, 영문·숫자·특수문자 포함 |
| `nickname` | ✅ | 20자 이하, 중복 불가(대소문자 무시) |
| `aptName` | ✅ | 100자 이하 |
| `dong` | | 20자 이하 |
| `ho` | | 20자 이하 |

회원이 직접 적는 값(`nickname`, `aptName`, `dong`, `ho`)은 스크립트가 될 만한 입력을 걸러 냅니다.

**201 Created**

```json
{
  "message": "회원가입에 성공하였습니다",
  "user": { "id": 1, "nickname": "나눔이", "aptName": "행복아파트", "dong": "101", "ho": "1502", "role": "USER" }
}
```

토큰을 주지 않습니다. 가입 뒤에는 로그인을 따로 불러야 합니다.

| 오류 | 이유 |
| --- | --- |
| 400 | 형식 위반 |
| 409 | 이메일 또는 닉네임 중복 |
| 429 | 한 IP 에서 1시간에 5번을 넘김 |

> 429 는 성공·실패를 가리지 않고 **시도 자체를** 셉니다. 중복 이메일 응답(409)만 보고 가입 여부를 훑는 것을 막기 위함입니다.

## POST /api/auth/login

로그인. 인증 필요 없음.

```json
{ "email": "nanumi@example.com", "password": "Ab3!efgh" }
```

**200 OK**

```json
{
  "accessToken": "eyJ...",
  "refreshToken": "eyJ...",
  "user": { "id": 1, "nickname": "나눔이", "aptName": "행복아파트", "dong": "101", "ho": "1502", "role": "USER" }
}
```

| 오류 | 이유 |
| --- | --- |
| 401 | 이메일이 없거나 비밀번호가 틀림 (**둘을 구분해 알려 주지 않습니다**) |
| 403 | 이미 탈퇴한 계정 |
| 429 | 실패 횟수 초과 |

없는 이메일로 시도해도 있을 때와 같은 시간을 씁니다. 응답 시간만 보고 가입 여부를 알아내는 것을 막기 위해 가짜 해시를 한 번 돌립니다.

## POST /api/auth/refresh

액세스 토큰 재발급. 인증 필요 없음(리프레시 토큰이 곧 자격 증명).

```json
{ "refreshToken": "eyJ..." }
```

**200 OK**

```json
{ "accessToken": "eyJ...", "refreshToken": "eyJ..." }
```

**리프레시 토큰도 새로 나옵니다(회전).** 둘 다 갈아 끼워야 하며, 보낸 토큰은 그 즉시 못 쓰게 됩니다.

| 오류 | 이유 |
| --- | --- |
| 401 `만료된 리프레시 토큰입니다.` | 기한이 지났거나 로그아웃된 토큰 |
| 401 `유효하지 않은 토큰입니다.` | 서명이 맞지 않음, 액세스 토큰을 보냄, 또는 **이미 쓴 토큰을 다시 보냄** |

마지막 경우에는 그 계정의 **모든 기기가 로그아웃됩니다.** 토큰이 새어 나갔을 가능성을 세션 유지보다 위에 두기 때문입니다.

> 이 때문에 탭 여러 개가 같은 토큰으로 동시에 재발급을 부르면 안 됩니다. 프런트는 Web Locks 로 한 번에 하나만 돌게 하고, 부르기 직전에 저장소에서 토큰을 다시 읽습니다(`frontend/src/api/axiosInstance.ts`).

## POST /api/auth/logout

로그아웃. **인증 필요.**

```json
{ "refreshToken": "eyJ..." }
```

몸통은 없어도 됩니다.

| 보낸 것 | 결과 |
| --- | --- |
| 리프레시 토큰 | 그 기기만 로그아웃 |
| 비었거나 몸통 없음 | 이 계정의 **모든 기기** 로그아웃 |

**200 OK**

```json
{ "message": "로그아웃이 완료되었습니다." }
```

남의 토큰을 지워 달라고 보내도 무시됩니다(계정이 맞는지 확인합니다).

> **이미 발급된 액세스 토큰은 취소되지 않습니다.** 최대 15분 동안 그대로 통합니다.

## POST /api/auth/withdrawal

회원탈퇴. **인증 필요.**

```json
{ "password": "Ab3!efgh", "reason": "이사를 가서" }
```

`reason` 은 선택(255자 이하)이며, 개인정보 수집·이용 동의에 적어 둔 선택 항목입니다.

**200 OK**

```json
{ "message": "회원탈퇴가 완료되었습니다.", "withdrawnAt": "2026-10-01T12:00:00" }
```

| 오류 | 이유 |
| --- | --- |
| 401 | 비밀번호가 틀림 |
| 403 | 이미 탈퇴한 계정 |
| 404 | 계정을 찾을 수 없음 |

탈퇴하면 모든 기기가 로그아웃되고, 그 뒤로는 남아 있던 액세스 토큰도 통하지 않습니다(`ActiveUserGuard`). 개인정보는 **탈퇴 후 30일이 지나면 실제로 지워집니다**(`WithdrawnDataPurgeService`).

## 상태 확인

인증 없이 열려 있고 상태값만 내려줍니다.

| 경로 | 보는 것 |
| --- | --- |
| `GET /actuator/health/liveness` | 앱이 살아 있는지 (Render 배포 판정용) |
| `GET /actuator/health/readiness` | 앱 + DB 연결 (감시용) |
| `GET /actuator/health` | 전체 합계 |

`/actuator` 의 다른 경로는 닫혀 있습니다(401).

## 아직 없는 것

구현 범위 밖입니다. 출시 필수인지는 정해지지 않았습니다. 자세한 영향은 `docs/deployment.md` 의 "아직 구현 범위 밖인 것" 에 적어 두었습니다.

| | 상태 |
| --- | --- |
| 비밀번호 찾기·재설정 | 없음 |
| 이메일 소유 확인 | 없음 |
| 이메일·비밀번호 변경 | 없음 |
| 내 정보 조회·수정 | 없음 |
| 나눔글 (등록·목록·상세) | 없음 |
| 주소 검색 API 연동 | 없음 (화면에서 직접 입력) |
